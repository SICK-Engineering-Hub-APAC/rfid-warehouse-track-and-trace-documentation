Troubleshooting

Start with the symptom, check basic power/network/configuration, then use system records for evidence.

Symptom Likely cause Action
Cannot sign in to Admin Wrong URL/credential or service unavailable Confirm the Admin Web URL and use admin@sick.com with the current deployment password. If it was changed, contact the administrator.
Viewer cannot edit Expected read-only behavior This is expected for a Viewer account. Sign in with an Admin account when a configuration change is required.
Device shows Offline Power/network/device heartbeat mismatch Check power, cable/Wi-Fi, IP, Device ID and connection-check settings.
Dispatch RFID reader Offline RFID reader IP/port/framing or network issue Ping/test the configured RFID reader address, verify reader Settings, and restart the connection only after checking configuration.
MQTT Disconnected Broker URL/credentials/network issue Use app connection test; verify broker host/port and credentials.
Asset RFID not recognized Invalid EPC, tag not registered, wrong reader field Confirm Tag ID in Assets and read the EPC with a known reader. Default unknown-tag alert is disabled.
Wrong Shipment Asset Asset tag belongs to another Shipment Remove the Asset from the current transaction and use the correct Shipment workflow.
Rack QR not recognized Damaged/wrong QR or Rack not present Regenerate/download Rack QR from Admin and verify the Rack exists.
Rack/Location mismatch Handheld Location does not match Rack Location Correct Handheld Location Settings or choose the correct Rack.
Movement stays Pending Destination event not received Check physical route, destination Gantry health and pending movement details.
Movement Timed Out Travel/detection exceeded configured timeout Find Asset physically, check devices/rule timeout, then resolve/replan safely.
Invalid route/out-of-order alert Wrong sequence or no matching enabled rule Review movement plan and RFID Movement rules before retry.
Shipment tag-count alert Expected registered tagged Asset not observed in Gantry window Check all expected Assets/tags and RF coverage; verify correct Shipment workflow.
Printer cannot encode Wrong printer IP/model/network/tag Verify the configured RFID printer address, printer ready state and printer model; retry with a known tag.
Handheld waiting for confirmation Event queued/published but system result not received Check API/MQTT connectivity; keep workflow intact and allow sync/reconnect.
Handheld FAILED/PARTIAL System rejected some/all reads Review listed Assets and Shipment/Rack validation, correct issue and retry.
Dispatch Confirm disabled Blocking validation or offline dependency Check Central service, MQTT and RFID reader status, then remove or correct wrong/unknown/ineligible tags.
Alert popup disappeared Popup timer expired Open Alerts; unresolved Alert remains until resolved/acknowledged.
IP address conflict on a device network Gantry local device networks are accidentally bridged or duplicated IP ranges overlap Compare with the approved IP plan. Use SOPAS ET for supported SICK devices, the device webpage for TDC-X/PicoScan, or the third-party device's own network interface. Then retest connectivity.
App restarted during transaction Pending state requires recovery Allow app to restore persisted state; do not create a new duplicate transaction until status is known.

When to stop and escalate

  • Same Asset appears completed in one application but failed in Admin.
  • Multiple devices appear to use the same IP address on one physical network.
  • An RFID rule change unexpectedly modifies Asset status/location.
  • Repeated Gantry events create unexpected duplicate movements.
  • An RFID reader, direction sensor, printer, or other field device requires firmware-level or engineering-tool diagnosis beyond basic network checks.
